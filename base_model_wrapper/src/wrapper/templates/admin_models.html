Column & action reference

app state · live — Modal app state (deployed means the app exists; initializing means it's coming up) plus the live container count from Modal. A deployed app with 0 live is scaled to zero (no cost, cold-boot on next request).
scaling (deploy-time) — min_containers / max_containers / scaledown_window from the model registry, baked into the Modal app at deploy time. Runtime overrides via Keep warm / Release / warm window are not echoed here — the live count and the warm-window summary on each row reflect the actual runtime state.
Stop — tears down all containers (modal app stop); costs $0/hr while stopped. Re-deploy to use again.
Keep warm — sets min_containers=1 at runtime. One container stays hot indefinitely; eliminates cold-boot latency. Cost runs continuously (~$36/hr for 8×H200, ~$5/hr for 1×H100).
Release — sets min_containers=0. Container becomes eligible to scale down after scaledown_window idle.
Deploy — runs MODEL_ID=<id> modal deploy modal_app.py from inside this container. Idempotent (~1.6 s if already deployed). Also pings the model to start cold-boot warming.
Warm window — APScheduler crons that flip min_containers on a recurring schedule. warm_cron fires set_min_containers=1; cool_cron fires set_min_containers=0. Standard 5-field cron in the supplied timezone. Lives in the wrapper DB; edits take effect on save without a Modal redeploy.

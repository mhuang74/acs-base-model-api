Capacity probe

Periodically requests an 8×H200 container on Modal and records whether the allocation succeeded and how long it took. 8×H200 is the shape Trinity-Large-TrueBase, Llama-3.1-405B, and Kimi-K2-Base all need, so a successful probe means any of those models can be cold-booted right now. Trinity is currently the model that surfaces H200 capacity issues most often, but the probe itself isn't Trinity-specific. Fired by APScheduler in this wrapper service (not Modal's own cron), which is why the schedule is editable here without a Modal redeploy.

Standard 5-field cron (UTC): minute hour day-of-month month day-of-week. Default 0 7,10,14,16,19,23 * * * fires six times per day at 07:00, 10:00, 14:00, 16:00, 19:00, and 23:00 UTC. Each fire boots an 8×H200 container for ~1 min (~$0.60 per fire, ~$3.60/day on the default schedule). Use */N * * * * for "every N minutes" if you want denser sampling during an investigation.
Trigger now — fires a one-off probe immediately, outside the schedule. Useful before deploying a large model to check whether H200 capacity is currently constrained.
